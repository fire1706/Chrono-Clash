# Étape M7 — Équilibrage, performances et serveur dédié

## 1. Équilibrer avec les simulations

Le simulateur fait jouer 10 bots entre eux, en accéléré et sans affichage, avec **exactement le même code que le jeu** :
un réglage modifié dans `data/*.json` se retrouve directement dans les résultats.

```
dotnet run --project src/ChronoClash.Server -c Release -- simulate --matches 20 --mode classic
dotnet run --project src/ChronoClash.Server -c Release -- simulate --matches 30 --mode quick --difficulty hard --out quick-hard.csv
```

Options : `--matches`, `--mode classic|quick`, `--difficulty easy|normal|hard`, `--theme temperate|archipelago|desert|winter`,
`--threads` (parties en parallèle, par défaut tous les cœurs), `--seed` (pour rejouer exactement les mêmes parties), `--max-minutes`, `--out fichier.csv`.

Le rapport affiche : durée des parties, première élimination, phase de zone à la fin, ères atteintes, taille des armées,
usage des objectifs, taux de victoire par personnalité, vitesse de simulation. Il compare aux **cibles** et propose quoi régler :

| Cible | Classique | Rapide |
|---|---|---|
| Durée d'une partie | 15 à 20 min | 6 à 9 min |
| Ère médiane du vainqueur | environ 4 (1914-18) | environ 3 (Renaissance) |
| Personnalités | aucune ne gagne 3 fois plus souvent qu'une autre | idem |

**Méthode conseillée** (celle utilisée pour le prototype) :
1. Lancer 20 à 30 parties dans le mode à régler, noter le rapport.
2. Changer **un seul** réglage à la fois (voir le tableau ci-dessous), relancer avec la même `--seed`, comparer.
3. Garder ce qui rapproche des cibles, puis tester en jouant vraiment (le ressenti compte autant que les chiffres).

| Symptôme | Réglage |
|---|---|
| Parties trop longues / trop courtes | `tuning.json` → `zone.phases[].wait`, `combat.damageMultiplier` |
| Les bots se battent trop tôt / trop tard | `tuning.json` → `difficulty.*.grace`, `ai.ramp`, `difficulty.*.ratioStart/ratioEnd` |
| Évolution trop lente / trop rapide | `eras.json` → `threshold` ; `tuning.json` → `bubbles.pointsPerTroopBubble`, `combat.chiefPoints` |
| Une personnalité domine | `bots.json` → valeurs de cette personnalité |
| Armées trop grosses / trop petites | `tuning.json` → `bubbles.troopBubbleTarget` ; `troops.json` → `gain`, `cost` |

## 2. Performances

- Les couleurs des troupes, bulles et de la minicarte sont lues une fois au lieu de chaque image.
- La minicarte se redessine 10 fois par seconde au lieu de 60.
- Le cœur peut faire tourner plusieurs parties en parallèle (listes de travail par fil d'exécution) : utile pour les simulations et un futur serveur multi-parties.
- Repère : la ligne « Vitesse de simulation » du rapport doit rester très au-dessus de 20 ticks/s (sinon le jeu ralentirait en fin de partie chez l'hôte).
- Si le jeu rame avec de très grosses armées : **Réglages → Qualité basse**. Prochaine piste si besoin : dessin des troupes en MultiMesh (un seul appel de dessin par type de troupe).

## 3. Serveur dédié

Le serveur dédié est **le jeu lui-même, lancé sans affichage**. Personne ne joue dessus : le premier joueur connecté
**mène le salon** (bouton « Lancer la partie », avec les réglages de son écran de préparation). Quand tout le monde est parti,
le serveur revient au salon pour une nouvelle partie.

**Sur ton PC (test)** :
```
"C:\…\Godot_v4.7.2-stable_mono_win64.exe" --path game --headless -- --server --port 7777
```
Puis, dans le jeu : Jouer → Rejoindre `127.0.0.1`.

**Sur un serveur loué (Linux)** :
1. Dans Godot : Projet → Exporter → préréglage **« Serveur dédié (Linux) »** (déjà prêt dans `game/export_presets.cfg`) → Exporter. Il faut avoir installé les modèles d'export .NET de Godot 4.7.2.
2. Copier le fichier exporté sur le serveur, puis : `./ChronoClash.x86_64 --headless -- --server --port 7777`
3. Ouvrir le port **UDP 7777** dans le pare-feu du serveur. Les joueurs rejoignent l'adresse IP du serveur.
4. Pour qu'il redémarre tout seul, le déclarer comme service (systemd) — à faire avec l'hébergeur ou demande-moi le fichier.

Un petit serveur (2 cœurs, 2 Go de mémoire) suffit pour une partie à 10.

## 4. Exporter le jeu pour les joueurs

Les traductions (`translations/*.json`) sont incluses grâce au filtre déjà réglé.
